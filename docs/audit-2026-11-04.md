# Audit: core XPRS functionality outside the core (2026-11-04)

Measured against `app/docs/architecture.md` (all of it) and
`app/docs/performance.md` (§1, §4.2, §6.5, §8). Every finding below was
confirmed by reading the code at the cited line; grep hits alone were not
counted. Nothing was changed.

"The core" here means what architecture.md §1 says it is: identity and keys,
transports, delivery (LXMF, courier, custody, retries), storage. Section 3's
test decides placement: *moves bytes between devices → core, without
exception; needs a key, the profile or a database → core, behind one narrow
`hal_*` verb; means something to one application → wapp; is a screen → wapp or
a core surface.*

## Summary

| # | Where core functionality is | Severity | Count |
|---|---|---|---|
| 1 | **Inside wapps** (C, `xprs-dev/apps`) | no high findings among the maintained wapps | 3 medium, 5 low |
| 2 | **Inside the app's screen layer** (`lib/wapp/wapp_page.dart`, launcher) | lane choice, publishing, reachability in widget code: **high** | 20+ Social special cases |
| 3 | **Core services that know a specific wapp, or import the UI** | **high** | 4 cases (+1 dead Circles service) |
| 4 | **Core services not in `core`** (still in the app repo) | structural | 117 files, ~54k lines |
| 5 | **performance.md violations in core code** | 5 high, 9 medium | |
| 6 | **Gaps in `arch_guard`** that let 1–3 through | | 5 rules too narrow |

Circles and Mail are deprecated and are left out of the findings. What the
core and the HAL still carry only for them is listed in §1.4 as code to delete
with them.

## 7. Order of work

1. **Make `core` the core.** Cut the four seams that hold most of section 4:
   `xprs_sig` → a signer interface (`NostrSigner` already exists in core);
   `ProfileDb` → a database handle passed in; `PreferencesService` → a
   key-value interface plus the policy snapshots that already exist;
   `WappEventBroker` → a core event sink the app adapts. Then move the receive
   door, the archive, the courier and the publisher, with the guard's rules.
2. **Move core storage out of the UI**: `sharedMediaArchive`, `ActivityArchive`,
   `AndroidForegroundService` (behind a power/keep-alive interface), launcher
   visibility (behind an "is anyone looking" interface).
3. **Delete what only Circles and Mail used** (§1.2): the `hal_rns_*` and
   `hal_relay_*` verbs, the Circles rendezvous in `RnsService`, the
   `hal_relay_reachable` exemption. Then give Files and Things the core pieces
   they lack (core LAN discovery, a per-followed-station topic).
4. **Take Social out of `wapp_page.dart`**: the lane choice, publishing,
   reachability and backfill go to core services behind HAL verbs; Social's
   meaning (votes, counts, filters) goes to the wapp.
5. **Fix P1–P5** (each one is small).
6. **Widen the guard** (section 6) so none of this can come back unseen.

## 8. Status after the fixes (2026-11-04, same day)

**Section 4 (core services in the app repo): done.** Of the 117 files and
~54k lines, the core is now here; the app keeps an export shim at each old
path. What remains in the app's `lib/services` and `lib/connections` is the
app's own platform and host code, reached by the core only through
`CoreHost` seams: the BLE platform service and its Reticulum glue, WiFi-Direct,
Android's USB serial, `open_path`, the notification/deep-link/permission
services, the loopback admin API, the HAL glue and `rns_autostart` (boot
wiring). `core` builds, analyzes and tests with plain `dart`.

**Section 3 (core knowing a wapp, core importing the UI): done**, except:
- `kRvWappTag = 'circles'` (deprecated Circles; left, see §1.2).
- `rns_autostart.dart` keeps the observed-nodes database in the Mesh wapp's
  folder (`wappDataStorageFor(prefs, 'mesh')`). Moving it is a data
  migration on every installed device; left in the baseline.

The Social database write is gone (nothing read it); notifications are
raised by topic (`core:nostr`) and routed by the host; the media store, the
feed store (`ActivityArchive`), the event broker and the foreground service
are no longer reached through `lib/wapp`.

**Section 2 (core decisions in the screen): partly done.**
- Done: the reaction's lane choice (`RnsService.react`), the presence verdict
  (`RnsService.inReach`, used by the chat header and the rooms list), and the
  `social.note` publish path (one host function, `lib/wapp/wapp_notes.dart`,
  instead of a copy in the page and one in the headless engine).
- Left, deliberately: the **feed and group backfill** in `wapp_page.dart`
  (a 3-minute timer and a 15 s fast phase that call `fetchFeedBackfill` per
  topic and merge into the page's conversation stores). It duplicates what
  `XprsCatchup`/`XprsFetch` do, and the fix is a redesign of how a wapp's
  conversations receive history (core fetches and publishes on the broker;
  the wapp's store takes it), which changes message delivery and needs a
  device to verify. And the **~20 `_wappName == 'social'` branches**: Social's
  feed is rendered by the host, and each branch needs a capability a manifest
  can declare instead. Both stay in the baseline (`no-core-calls-from-screen`,
  `no-wapp-special-case-in-host`).

**Section 5 (performance): P1, P2, P4 and the content log fixed** (bounded
inbound LXMF links, bounded `_lxmfInbox`, ranged media reads, no words in the
log). P3 and P6 are left with the reason in performance.md §8.24. P5 goes with
Circles. P12 (a log line per engine batch, now a one-a-minute summary) and P14 (a log line per probe, now per-interface counts in the perf: line; the per-sender reply map pruned) are fixed. P7-P11, P13 and P15 are recorded and not yet fixed: each changes a cadence or a concurrency shape (timers onto the native heartbeat, a worker queue for redaction, a completer for the swarm) and wants a device to measure before and after (performance.md §4.1).

**Section 6 (the guard): done.** New rules `core-imports-ui`,
`no-wapp-special-case-in-host`, `no-core-calls-from-screen`,
`no-sub-minute-interval-constant`, `no-content-in-log`; widened
`no-app-logic-in-core` (including `source: 'wapp:<name>'`), `hal-budget`,
`no-transport-logic-in-wapps-repo` and `no-sub-minute-poll` (multi-line). The
guard scans `../core/lib/src` with the app's rules. Baseline: 89 before the
audit, 208 with what the new rules found, 156 after these fixes.

### How the move was done (reusable for the rest)

1. **Find the frontier.** Follow every import from the core-layer files and
   list the Flutter-bound files they reach, with how many core files reach
   each. Cutting one edge at a time showed nothing (the core was one tangled
   cluster); the frontier showed the few edges everything went through
   (`RnsService` -> `NotificationService` -> the launcher; the broker ->
   `wapp_engine`; `PreferencesService` <-> `ProfileService`).
2. **Cut each edge** with a `CoreHost` seam (the calls actually made, a
   headless default) or by moving the dependency down (the broker once it
   took a wake-up callback; `ActivityArchive`; `PowerState` once lifecycle
